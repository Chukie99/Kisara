# 2026-10-15 — Kuota ZeroGPU habis: gambar gagal beruntun

## Keluhan user
"udah di fix?" — user menjalankan pipeline satu-klik dan **semua gambar gagal**. Log app penuh baris:
`[job image] Error: Space-nya gagal menyelesaikan permintaan. Biasanya kuota ZeroGPU harian sudah habis…`
Stack menunjukkan `Promise.all (index 1..7)` di `runPipeline` — jadi 8 gambar diminta hampir bersamaan.

## Diagnosis (direproduksi, bukan tebakan)
Memanggil Space langsung dengan curl membalas persis:
```
event: error
data: null
```
Space berstatus `RUNNING` di hardware `zero-a10g`, tapi menolak kerja. Jadi **bukan bug app** — ini sisi Hugging Face.

Penyebab paling mungkin: **kuota ZeroGPU harian habis**. Kuota gratis = **5 menit GPU/hari**, dan reset-nya **24 jam setelah pemakaian pertama**, bukan tengah malam. Jadi sekali terpakai sore, seharian berikutnya masih memakai jendela yang sama. (Tes-tes gambar saya kemarin malam ikut memakan kuota user — perlu diakui.)

Catatan: pesan error yang muncul sekarang **adalah hasil perbaikan kemarin** (`streamError` menerjemahkan `data: null` jadi kalimat yang berguna). Sebelumnya cuma `Error: null`.

## Perbaikan yang dikerjakan
1. **`src/main/services/huggingface.ts`** — `generateImage()` dipecah: isi lamanya jadi `drawOnce()`, dan `generateImage()` mencoba **2 kali** dengan jeda 4 detik. Space ZeroGPU bersama kadang menolak saat serah-terima GPU atau saat antreannya penuh; satu percobaan ulang menyelamatkan gambar yang sedang ditunggu user. Kalau sinyal sudah dibatalkan, tidak diulang.
2. **`src/main/ipc.ts`** — `runPipeline()` tidak lagi menembak semua gambar sekaligus (`Promise.all`) kalau `imageProvider === 'huggingface'`; sekarang **satu per satu**. Layanan lain (Cloudflare/Higgsfield) tetap paralel.

Typecheck + build bersih.

## Jalur cadangan yang terverifikasi siap
`settings.testKey('cloudflare')` dijalankan lewat dev harness:
```json
{ "ok": true, "message": "Terhubung · stable-diffusion-xl-base-1.0 siap · kuota gratis 10.000 neurons/hari" }
```
Jadi **Cloudflare adalah penyelamat langsung**: kuncinya sudah ada dan bekerja, kuota hariannya jauh lebih longgar daripada ZeroGPU 5 menit. Kualitasnya SDXL (di bawah FLUX), tapi yang penting jalan. Setelan user saat itu masih `imageProvider: "huggingface"` (yang sedang rusak) — **belum saya ubah**; saya tawarkan dulu ke user.

## Langkah berikutnya untuk user (ditawarkan, belum dikerjakan)
- Ganti provider gambar ke **Cloudflare** di Pengaturan → gambar langsung bisa dibuat lagi.
- Atau tunggu jendela kuota ZeroGPU 24 jam, lalu pakai HF lagi untuk kualitas lebih tinggi.
- Untuk kualitas terbaik tanpa batas ketat: unggah `app.py` baru + `HF_TOKEN` (FLUX), atau HF PRO ($9/bln → 40 menit/hari).

## Catatan
App ditutup user setelah percobaan itu; perlu dijalankan ulang sebelum dicoba lagi.

# 7 gerakan kamera baru + temuan FLUX Cloudflare

## Permintaan user
1. "paling best pake gaya apa visual apa" (dengan FLUX)
2. Butuh **sound effect** (sirine, jangkrik, air netes, jumpscare) — "dimana?"
3. "pengen nambahin animasi kamera biar gak monoton" — bisa ditambah?

## Yang dikerjakan: 7 preset kamera baru
`CameraPresetId` (di `shared/types.ts`) bertambah dari 7 → **14**. Semua ditulis sekali di `shared/motion.ts` sehingga pratinjau dan ekspor tetap sama (aturan #1 di AGENTS.md):

| Baru | Gerakan |
|---|---|
| `panup` / `pandown` | geser vertikal |
| `zoomleft` / `zoomright` | dorong serong (zoom + geser diagonal) |
| `reveal` | mulai dekat lalu mundur memperlihatkan seluruh tempat |
| `rotate` | putar pelan, −12°·s → +12°·s |
| `handheld` | dua gelombang lambat per sumbu (bukan rattle cepat seperti `shake`) |

**Rotasi butuh kerja ekstra:** `CameraFrame` dapat field `rot?`; `cameraCss()` menambah `rotate(...)`; `cameraPerspective()` memutar **keempat sudut jendela** mengelilingi pusatnya memakai `cos`/`sin` di ekspresi ffmpeg. Zoom pada preset `rotate` sengaja dilebihkan (`1 + s*0.6 + 0.05`) supaya sudut yang berputar tetap di dalam gambar — kalau tidak, muncul baji hitam di tepi. Sudut maksimum ±3° pada kekuatan `kuat`; perhitungan menunjukkan butuh zoom ≥ 1,092 dan preset memberi 1,20.

**Terverifikasi dengan ffmpeg asli** (bukan cuma typecheck): tiap filter dijalankan pada pola `testsrc2` 1920×1080 → 60 frame per preset, semuanya sukses. Montage 4 frame untuk `rotate` memperlihatkan kemiringan progresif **tanpa celah hitam**; `reveal` benar-benar makin menjauh dan `zoomleft` mendorong serong. Skrip uji memakai `node --experimental-strip-types` + impor `file:///F:/...motion.ts` (path Windows wajib bentuk file:// URL).

Di `story.ts`, deskripsi field `camera` diperluas supaya LLM tahu kapan memakai tiap gerakan.

## TEMUAN: user memakai FLUX lewat CLOUDFLARE, dan hasilnya kotak
Setelan user: `imageProvider = "cloudflare"`, `cloudflareModel = "@cf/black-forest-labs/flux-1-schnell"`. Jadi "keren pake flux" itu **FLUX di Cloudflare**, bukan Space HF (Space masih `playgroundai/playground-v2.5-1024px-aesthetic`).

**Masalahnya:** schema resmi `@cf/black-forest-labs/flux-1-schnell` (developers.cloudflare.com) hanya menerima `prompt` dan `steps` — **tidak ada `width`/`height`**. Jadi FLUX di Cloudflare selalu mengembalikan gambar **kotak 1024×1024**, dan app memotongnya ke 16:9 atau 9:16 → bagian gambar hilang. Asset user membuktikan campuran ukuran: `1344x768` dan `1024x1024`.

**Perbaikan yang dibuat:** `shortClipPrompt` di `generation.ts` kini menyisipkan petunjuk komposisi sesuai rasio proyek ("Vertical 9:16 composition, main subject centred…" / "Wide 16:9 composition…") supaya subjek tidak diletakkan di tepi yang akan terpotong. Ini membantu SDXL juga.

## Yang BELUM dikerjakan: sound effect
App **tidak punya dukungan SFX sama sekali** — hanya narasi + satu trek musik latar (`editor.musicAssetId`). Untuk sirine/jangkrik/air netes/jumpscare perlu lapisan audio baru (mirip sistem `Overlay` yang sudah ada untuk gambar/teks: punya `start`/`end` dan id aset). Belum ditawarkan implementasinya ke user.

Sumber SFX gratis yang layak disebut: Pixabay Sound Effects (bebas, tanpa atribusi), Freesound (CC, cek per file), Mixkit, YouTube Audio Library, Zapsplat, Myinstants (jumpscare/meme).

# Bug konsistensi karakter + budget prompt Cloudflare FLUX

User bertanya "apa lagi yang kurangnya". Saat menelusuri, ketemu **dua bug nyata** di jalur gambar gratis (`src/main/generation.ts`):

## 1. Deskripsi karakter cuma terkirim sepotong (akar masalah "wajah beda tiap adegan")
`shortClipPrompt` mengirim `${c.description.split(',')[0]}` — hanya **segmen sebelum koma pertama**. Contoh nyata dari DB, karakter "Jonas Salk":
- deskripsi penuh: *"A human male scientist in his late 30s, with neat dark hair, wire-rimmed glasses, a thoughtful and determined expression, and a fair skin tone. Default outfit: A white lab coat…"*
- yang benar-benar dikirim ke model: **"A human male scientist in his late 30s"**

Kacamata, rambut, ekspresi, warna kulit, dan seluruh baju hilang. Wajar kalau orangnya berubah di tiap adegan.

**Perbaikan:** kirim `c.description` utuh dengan jatah `clipPart` yang lebih besar (340 char untuk model modern, 110 untuk SDXL — sebelumnya 70). Jatah bagian lain diseimbangkan (setting/action 420→380, avoid 160→150) dan `MODERN_PROMPT_LIMIT` dinaikkan **1600 → 1800**.

## 2. FLUX di Cloudflare hanya dapat jatah prompt SDXL
Di pemanggilnya: `provider === 'huggingface' ? await huggingfacePromptLimit() : SDXL_PROMPT_LIMIT` — jadi **Cloudflare selalu dapat 480 karakter**, padahal setelan user `cloudflareModel = "@cf/black-forest-labs/flux-1-schnell"` yang sanggup prompt panjang.

**Perbaikan:** fungsi baru `freePromptLimit(provider)` yang memeriksa model yang benar-benar akan menggambar — untuk Cloudflare melihat `getSettings().cloudflareModel`, untuk HF menanyakan `huggingface.activeModelName()`. Konstanta `SDXL_FAMILY` dipakai bersama (kini termasuk `stable-diffusion`).

Typecheck + build bersih; app dijalankan ulang.
